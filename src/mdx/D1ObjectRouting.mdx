#### Where your Drizzle code runs

The Worker receives HTTP requests and routes them to a database object. It does not create the Drizzle client itself.

When the Worker calls `env.YourDatabase.idFromName(objectName)` and `env.YourDatabase.get(id)`, it gets a Durable Object stub for one logical database. Wrapping that stub with `createD1ObjectSession()` gives you a typed client for the methods on that database object:

```typescript
const id = env.YourDatabase.idFromName(objectName);
const stub = env.YourDatabase.get(id);
const db = createD1ObjectSession<YourDatabase>(stub);

const result = await db.client.someApplicationMethod();
```

Those methods run inside the Durable Object, next to SQLite. Put the Drizzle client and the application code that uses it on the object class:

```typescript
export class YourDatabase extends DrizzleD1Object<Env> {
  db = drizzle(this.ctx, { schema });

  async someApplicationMethod() {
    return this.db.select().from(users).all();
  }
}
```

#### How writes reach the primary

With this setup, Cloudflare can keep read replicas close to users. `DrizzleD1Object` enables read replication by default on the primary object. The primary can read and write, while replicas are read-only.

Mark write methods with `d1PrimaryMethods()` so calls that land on a replica forward to the primary before your method body runs:

```typescript copy
import { DrizzleD1Object, d1PrimaryMethods, drizzle } from 'drizzle-orm/d1-object';

export class YourDatabase extends DrizzleD1Object<Env> {
  static override readonly primaryMethods = d1PrimaryMethods<YourDatabase>()('createUser');

  db = drizzle(this.ctx, { schema });

  async createUser(input: typeof users.$inferInsert) {
    return this.db.insert(users).values(input).returning().get();
  }
}
```

Unmarked writes and transactions throw on replicas instead of being query-forwarded. `applyDrizzleMigrations()` already forwards migrations to the primary. Raw SQL is write-classified by default; use `db.d1.readAll()`, `db.d1.readGet()`, or `db.d1.readValues()` for explicit raw reads that may run on replicas.

To disable read replicas for an object, pass `readReplication: false` to the base class:

```typescript copy
export class YourDatabase extends DrizzleD1Object<Env> {
  constructor(ctx: DurableObjectState, env: Env) {
    super(ctx, env, { readReplication: false });
  }

  db = drizzle(this.ctx, { schema });
}
```

#### When to use bookmarks

A bookmark is an opaque marker for a point in the object's write history. Use one when a client writes data and a later request must read at least that state, even if the read is served by a replica.

You do not pass bookmarks into your object methods. Pass the incoming bookmark to `createD1ObjectSession()` and return the session's updated bookmark:

```typescript copy
const db = createD1ObjectSession<YourDatabase>(
  env.YourDatabase.get(env.YourDatabase.idFromName(objectName)),
  { bookmark: request.headers.get('x-d1-bookmark') },
);

const result = await db.client.someReadMethod();

return Response.json(result, {
  headers: { 'x-d1-bookmark': db.getBookmark() ?? '' },
});
```

Omit the bookmark option and response header when stale reads are acceptable for that route.

Calls through one `createD1ObjectSession()` are serialized so each call uses the latest bookmark from the previous call. Use separate sessions for intentionally independent request chains.
